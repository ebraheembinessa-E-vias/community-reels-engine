# Stage 2: make the idea visible

Read `docs/styles.md` and `docs/workflow.md` from the package root. Verify the clean approval with the engine. A template is a starting vocabulary, not an excuse to apply the same decoration to every sentence.

For each sentence, ask what it does: compare, connect, demonstrate, list, count, or invite. Write `elements.json` on the clean timeline. Choose the smallest visual that explains that action. A real screenshot needs a provenance note and private data removed. If evidence is missing, request the specific asset or label the visual as an explanation; never fabricate a customer result.

Use Editorial for a clear explanation, Signal for a concentrated beat, or Diagram for a relationship/process. Give one recommendation based on the footage rather than a menu. Keep the face visible, the captions readable, and the safe areas clear. Arabic motion operates on shaped words/phrases, never separate letters. Keep Latin product names intact.

Run `dress` and `render`. Fix runtime errors and missing assets before showing the output. Review representative frames at entrances, holds and exits; check label clipping, face coverage, bidirectional text and ghost elements. Keep warnings visible in the handoff.

For an explicitly requested faceless reel, add `--faceless` to both commands. It omits the source picture and preserves approved audio. Plan meaningful visual beats across the whole explanation; do not leave an empty graphic background. The output stays separate from the talking-head version.

Run the hearing/visual review when authorized, verify its findings locally, then open the final video for the creator. Do not record final acceptance or publication on their behalf.
